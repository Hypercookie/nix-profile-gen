# Local MDM Server Integration Plan

## Goal

Extend nixmagic with an optional local MDM server so that macOS configuration
profiles generated by `home-manager switch` are pushed and installed
automatically, without the user having to double-click a `.mobileconfig` file.

---

## How It Would Work

```
nixmagic generates .mobileconfig
       ↓
NanoMDM serves & pushes it to the Mac
       ↓
Mac installs and enforces it
```

On every `home-manager switch`, nixmagic generates the payload profiles. NanoMDM
detects the new profiles and pushes them to the enrolled Mac automatically.

---

## Key Components

| Component | Tool | Cost |
|---|---|---|
| MDM server | NanoMDM (Go, single binary, ~3 deps) | Free / open-source |
| SCEP server | `micromdm/scep` | Free / open-source |
| TLS | Self-signed CA distributed via enrollment profile | Free |
| APNs push certificate | `mdmcert.download` (community signing service) | Free (see caveats) |
| Supervision / unremovable enforcement | Apple Business Manager (ABM) | Requires registered org + DUNS |

### NanoMDM
- https://github.com/micromdm/nanomdm
- Minimal Go binary implementing only the core MDM protocol.
- Does not include SCEP, TLS termination, ABM sync, or a command UI — those are
  composed separately.
- Designed for horizontal scalability; supports file, MySQL, and PostgreSQL storage.

### APNs Certificate (mdmcert.download)
- A community-run service that acts as a pre-approved MDM vendor.
- You submit a push CSR; they sign it; you upload to `identity.apple.com` with a
  free Apple ID and receive the MDM push certificate.
- No $99 Apple Developer Program account required.
- Caveats: Apple has not officially sanctioned the service. The signing cert could
  be revoked. Cert must be renewed annually. Intended for legitimate IT use, not
  purely personal device management.

---

## The "Unremovable" Limitation

`PayloadRemovalDisallowed: true` exists as a profile flag but macOS only
**enforces** it on *supervised* devices. macOS supervision requires Automated
Device Enrollment (ADE/DEP), which requires Apple Business Manager (ABM), which
requires a DUNS number (registered business identifier).

| Scenario | Achievable? |
|---|---|
| Profiles install automatically after `home-manager switch` | Yes |
| No $99 Apple Developer account | Yes (mdmcert.download) |
| Entirely local — no cloud MDM vendor | Yes (localhost loopback) |
| Profiles truly unremovable by the user | No — requires ABM (real org + DUNS) |

On iOS/iPadOS, Apple Configurator 2 can supervise a device locally over USB
without ABM. No equivalent workflow exists for macOS — supervision on macOS flows
exclusively through ADE/ABM.

---

## Network Architecture

For a single self-managed Mac the MDM server can run entirely on `localhost`:

- The Mac enrolls with itself (`https://localhost:<port>/mdm`).
- APNs outbound works normally behind NAT.
- The Mac's check-in calls reach loopback.
- TLS is required by the MDM client; a self-signed CA distributed via the
  enrollment profile satisfies this.

If the Mac leaves the network (e.g. travels), APNs push is still received but
the check-in HTTP call will fail until the machine is back and the server is
reachable again.

## Proposed Repository Structure

```
nixmagic/
└── mdm/
    ├── flake.nix (or integrated into root flake)  # exports NanoMDM service + tooling
    ├── nix-modules/
    │   └── mdm-server.nix      # launchd/systemd service wrapping NanoMDM + SCEP
    ├── enrollment/
    │   └── generate-enrollment.py  # generates enrollment .mobileconfig referencing
    │                               # localhost + self-signed CA
    └── certs/
        └── setup.sh            # one-time: generates self-signed CA, SCEP CA, TLS cert
```

### User Flow (after implementation)

1. `nixmagic-mdm setup` — generates certs, enrollment profile, starts NanoMDM.
2. Install enrollment profile once (manual double-click, one-time step).
3. From then on: `home-manager switch` → nixmagic generates profiles → NanoMDM
   pushes them → Mac installs automatically.
